# House to i3d – notes for Claude

Web app for building Farming Simulator 25 houses and exporting them as .i3d
(zipped with textures) for Giants Editor. Invite-only accounts, houses saved per user.

## Where things are
- backend/ Go API (stdlib net/http, SQLite by default, Postgres when DATABASE_URL is set): internal/auth, store, api, config, vision (Claude reads photos), cmd/server.
- frontend/ Next.js 16 (App Router, TypeScript); /api/* is proxied to the Go API.
  - src/editor/model.mjs = the core every building shares (settings, geometry, export, game-mod XML), no DOM. kinds/ = one module per kind of building, registered in kinds/index.mjs (which documents the
    interface; a kind imports only i3d.mjs, never model.mjs). layout.mjs = inside, wings, walls. i3d.mjs = the i3d writer. objects.mjs = game objects. openings.mjs = window and door styles.
    editor.mjs = controls and the three.js r128 preview, mounted by Editor.tsx.
  - src/builder/ = the modeller (props); src/app/ = the pages (My buildings, My items, My textures, the modeller, admin, API access); src/lib/ = the generate API for other programs.
- charts/building-creator-fs25 = Helm chart; docker-compose.yml runs api + web; CI in .github/workflows/ci.yml.
- docs/: DESIGN.md (how the pages look and behave: follow it), API.md, PLAN*.md (the plans; PLAN_MOD.md is the next big one), and
  **ARCHITECTURE.md = the detailed notes for every area (what it does, how it was decided, what is not tried in the game). Search it by keyword before working on an area, and update the paragraph when you change it.**

## How we work
- TDD: write the failing test first, then the code.
- A new or changed page follows docs/DESIGN.md (tokens, tabs with counts, one primary button, dialogs from components/dialog.mjs, `t()` on every text).
- Backend tests: cd backend && go test ./...  (TEST_DATABASE_URL=postgres://... also runs
  the store tests on Postgres; CI does both, on every pull request and on a release tag)
- CI runs the tests (backend, chart, frontend) and the Docker build check on every pull request to main (Lars, 2026-11-24; before that only on release tags), and the images, chart and
  release on a tag vX.Y.Z. A push to main runs nothing (no edge image, only releases are used).
- Pull requests (Lars, 2026-11-24): Claude makes one per piece of work, waits for CI (`gh pr checks --watch`), merges it when it is green (a merge commit, the branch deleted) and, when it is
  not, reads the log (`gh run view --log-failed`), fixes it on the same branch and pushes again; after three tries without progress it stops and says what is wrong. A PR that builds on another is
  merged after it, with its base changed to main first. Claude makes no release or tag, and changes no setting of the repository. Changes to the game's XML are marked "not tried in the game" in the PR.
- Chart tests: bash charts/test.sh (helm v4 in WSL at /usr/local/bin)
- Frontend tests: cd frontend && npm test (node --test, no browser needed)

## Dev environment (WSL)
- ./dev.sh starts API (:8080) + Next dev server (:3000); data in .dev/ (gitignored),
  ./dev.sh --reset wipes it. Reachable from the Windows browser at localhost:3000.
- Node 22 and gh live in ~/.local/bin (installed without sudo).
- Docker is not integrated into WSL; Docker Desktop runs on the Windows side.

## FS25 reference (read-only, on the Windows side)
- Game install: /c/Program Files (x86)/Farming Simulator 2025 (Git Bash path).
  shared/xml/schema/placeable.xsd is the authoritative placeable XML schema;
  data/placeables/brandless/gardenSheds/level01 is the template the export's
  area nodes (clear/level/test/tipOcclusion) and collision filter follow.

## Languages (i18n)
- English is the default; the language is the `lang` cookie (switcher in TopBar, LanguageSelect.tsx; AppConfig.tsx sets it and starts the translator). Texts: `frontend/src/i18n/locales/<lang>.json`, the English text is the key
  (`sv.json` = Swedish; `en.json` is generated by `npm run i18n`, which scans the source for texts + `scripts/i18n-extra.json`; `npm run i18n -- --missing` lists what a language lacks).
  A key with `{value}` matches any text of that shape (values translated recursively). index.mjs: `t(text, values)`, `translateText`; dom.mjs translates text nodes and placeholder/title/aria-label at runtime (MutationObserver);
  user-written names need `translate="no"`; confirm()/prompt()/texts put together in code use `t()`. Claude's photo guide stays English. A new language: add the json, an entry in LANGS and TEXTS (index.mjs).
